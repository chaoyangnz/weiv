# Weiv releasing

The canonical release contract is in daydream `shared/decisions/0001-canonical-release-process.md`.
The version entry points are `packages/weiv/package.json`, both supported platform package manifests, the main package's optional dependencies, and `site/site.json`. The macOS ARM64 binary under `packages/weiv-darwin-arm64/bin` is committed release input. The Linux x64 binary is built on the Ubuntu release runner from the same commit. Each platform's verification checks its native binary format and packs that binary. Publish both platform tarballs before the `weivjs` tarball, then verify a fresh install on both platforms. The VS Code extension lives in `packages/vscode-extension` and has its own Marketplace release flow.

Run `node tools/release.mjs plan --preflight-only` before expensive gates. For an offline rehearsal on a release candidate commit, run `node tools/release.mjs rehearse`; local experimentation on a dirty tree or existing version may use `--allow-dirty`. The rehearsal runs the component/runtime suite against the committed binary, checks the Vite plugin, packs npm tarballs, installs the main tarball in a local consumer, copies the verified tarballs into the local sink, checks their hashes, and renders `state/record.md`. It creates no tag or remote publication. The local component/runtime suite passed 170 tests and the Cyna suite passed 407 tests on 2026-11-10.

CI's manual `release-verify.yml` accepts version, platform (`macos-arm64` or `linux-x64`), and `preflight` or `verify`. Run `verify` for both platforms and compare the two `weivjs` tarballs before publication. It uploads packed tarballs and hashes for review. Public tagging and publishing are not wired. The former `publish-supported-release.yml` workflow was removed and `tools/publish-all.sh` is retired because they published before canonical verification.

Before public publication is wired, the verified artifacts must be consumed unchanged, with an annotated tag on the verified commit after all gates and registry packages published in dependency order. A release record belongs in `daydream/projects/weiv/docs/releases/` after publication.

After a version is published on npm and GitHub, run `node tools/sync-release-site.mjs` from the published Weiv commit. It checks the published version, syncs `site/` into the separate `neucine/sites` repository, builds and deploys weiv.dev, and verifies the live site. Set `WEIV_SITES_REPO` when using an isolated sites checkout. The sites checkout must be clean and at `origin/main`; its updated content lock is committed and pushed before deployment. Add this command after public package publishing when that path is wired.
